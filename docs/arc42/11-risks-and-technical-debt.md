# 11. Risks and technical debt

*Purpose: known risks and debt with mitigation · Audience: maintainers · As of 2026-11-07 · Sources: [`README.md`](../../README.md#project-status), [`PROVIDERS.md`](../PROVIDERS.md), [`BROWSER-AUTOMATION.md`](../BROWSER-AUTOMATION.md#limits), [`SECURITY-MODEL.md`](../SECURITY-MODEL.md#limits), [chapter 10](10-quality-requirements.md)*

Severity: high, medium, low. Owner is the maintainer team. Tracking is "GitHub issues": each row without an issue
link needs one before it is worked on (the repository states no issue numbers in its documents).

| ID | Risk or debt | Severity | Mitigation | Owner | Tracking |
|---|---|---|---|---|---|
| R-01 | **Browser automation is brittle.** Provider pages change; several bundled recipes were run against the real site only recently or not at all (see the `# STATUS` comment in each file of [`recipes/`](../../recipes)); providers may restrict automation in their terms. | high | Recipes are YAML data, fixable by pull request; unexpected state aborts and writes nothing; `browser run --dry` stops before creation; fake-driver tests; the team decides per provider ([BROWSER-AUTOMATION.md](../BROWSER-AUTOMATION.md#limits)). | maintainers | GitHub issues |
| R-02 | **Provider API changes and unverified endpoints.** Several provider modules were written from documentation and tested only against mocks (the *Verified* column of [PROVIDERS.md](../PROVIDERS.md) lists which). | high | Trial run with a throwaway token before real use ([TRIAL-RUN.md](../TRIAL-RUN.md)); a first rollout already found one provider bug; honest status per provider. | maintainers | GitHub issues |
| R-03 | **Single human bottleneck.** Every confirmation and every approval needs a human in the portal; approvals live in memory and vanish on restart. A sleeping or absent reviewer lets expiry dates pass. | medium | Expiry workflow raises issues at 30/14/7 days ([`secret-desk-expiry.yml`](../../examples/workflows/secret-desk-expiry.yml)); team sharing of the value-free configuration ([TEAM.md](../TEAM.md)). No delegation by design (D-03). | maintainers | GitHub issues |
| R-04 | **Early version.** 0.1.0, real-world testing mostly on macOS, not used in production at scale ([README](../../README.md#project-status)). | medium | Cross-platform workflow, simulated platforms, changelog ([CHANGELOG.md](../../CHANGELOG.md)); this chapter keeps the gaps visible. | maintainers | GitHub issues |
| R-05 | **Partial write leaves targets inconsistent.** If some targets accept the new value and others fail, the old value stays valid but the written targets already hold the new one until a retry (`partial: true` in `commitIssuanceOnce`). No dedicated test for this path (Q-REL-1). | medium | Old value is not revoked on failure; the result lists per-target outcomes; a retry rewrites. Add a test and a clear report text. | maintainers | GitHub issues |
| R-06 | **Orphan tokens after a restart.** Pending issuances are memory only. If the process stops while a review is open, the new token created at the provider is never revoked by secret-desk (inferred from `IssuanceQueue`; not covered by a test). | medium | The provider label contains the secret id and date so a human can find and delete it; trial-run clean-up steps. Consider listing and cleaning orphans at start. | maintainers | GitHub issues |
| R-07 | **Every merge to `main` publishes `:latest`.** Hosts that auto-update (optional Watchtower) pull each merge ([`release.yml`](../../.github/workflows/release.yml)). | low | The release job verifies first; the browser sidecar is published only when it changes; auto-update is optional and documented with its risk ([DOCKER.md](../DOCKER.md#automatic-updates-with-watchtower)). | maintainers | GitHub issues |
| R-08 | **Cross-platform CI is manual.** The Windows and Linux matrix runs only on `workflow_dispatch`, so a platform regression can reach `main` ([`cross-platform.yml`](../../.github/workflows/cross-platform.yml)); Q-OPER-1 is only partly met. | medium | Simulated platforms in unit tests; run the workflow before a release; consider a scheduled run. | maintainers | GitHub issues |
| R-09 | **Agents with shell access as the same OS user** can read the agent token and local files ([SECURITY-MODEL.md](../SECURITY-MODEL.md#limit-agents-with-shell-access-as-the-same-os-user)). | medium | Documented limit; run agents in a separate sandbox or OS user with only the agent token. | maintainers | GitHub issues |
| R-10 | **No accounts on the portal.** On a LAN the launch secret, cookie and host check are the only protection ([DOCKER.md](../DOCKER.md)). | medium | Publish to a trusted LAN only; never to the internet; persistent launch secret is a documented trade-off. | maintainers | GitHub issues |
| R-11 | **Mixed language in the code base.** Backend messages and many code comments are German; the English UI is produced by a translation table ([`i18n-en.ts`](../../packages/runtime/src/i18n-en.ts)). The project rule is English identifiers and messages for new code. | low | Coverage test for the table; migrate comments and messages gradually. | maintainers | GitHub issues |
| R-12 | **Documentation of decisions is recovered, not recorded.** No `docs/decisions/` folder; dates of D-01 to D-20 are unknown ([chapter 9](09-architecture-decisions.md)). | low | Record future decisions as ADRs. | maintainers | GitHub issues |
| R-13 | **No usability evidence and no coverage metric.** Q-USE-1 is open; Q-TEST-1 is partly met. | low | Run the trial-run checklist with a new reviewer; add a coverage report to CI. | maintainers | GitHub issues |
| R-14 | **Unasserted 15-minute limit.** The default and the 60-second sweep have no test (Q-SAFE-1). | medium | Add tests for `ttlMinutes` default and `IssuanceQueue.sweep`. | maintainers | GitHub issues |
