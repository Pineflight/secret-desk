# Documentation

Start with [GETTING-STARTED.md](GETTING-STARTED.md). The project overview is in the [README](../README.md).

## Guides

- [GETTING-STARTED.md](GETTING-STARTED.md): from a fresh checkout to the demo, your own configuration, a GitHub token with the exact permissions, the first reviewed renewal and a dev `.env`.
- [TRIAL-RUN.md](TRIAL-RUN.md): a guided first run with real services in a throwaway repository, with `doctor` pre-check and an acceptance list.
- [TROUBLESHOOTING.md](TROUBLESHOOTING.md): common errors (403 on environments, launch secret, ports, vault and keychain, Chrome, Windows paths) and their fixes.
- [FAQ.md](FAQ.md): short answers to frequent questions.

## Reference

- [CONFIGURATION.md](CONFIGURATION.md): every field of `secret-desk.config.yaml` and `inventory.yaml`, environment variables and files written.
- [CLI.md](CLI.md): all commands and options of the command line.
- [AGENTS.md](AGENTS.md): the MCP server, its 24 tools, skill installation and the policy for AI agents.
- [AGENT-API.md](AGENT-API.md): the HTTP reference of `/api/agent` (authentication, routes, errors, approval rules); [openapi-agent.yaml](openapi-agent.yaml) is the OpenAPI 3.1 description.
- [PROVIDERS.md](PROVIDERS.md): supported providers, their parameters, permissions per integration and how well each endpoint is verified.

## Concepts

- [STAGES.md](STAGES.md): stage kinds, how the GitHub environment is derived, custom stages and the team export.
- [COMPARE.md](COMPARE.md): the stage and repository comparison, cell states, parity, orphans, workflow needs.
- [REPOSITORIES.md](REPOSITORIES.md): repository selection, local folder links, path rules, search and renames.
- [INTEGRATIONS.md](INTEGRATIONS.md): permissions per integration, connecting tokens, test connection, write test and the vault.
- [TEAM.md](TEAM.md): exporting the value-free team file and onboarding new team members.
- [RECIPES.md](RECIPES.md): writing browser recipes for providers without an API; [BROWSER-AUTOMATION.md](BROWSER-AUTOMATION.md) explains the design and status.

## Design

- [ARCHITECTURE.md](ARCHITECTURE.md): how a new value flows from provider to GitHub, what data lives where, packages.
- [SECURITY-MODEL.md](SECURITY-MODEL.md): what is protected, how values are handled in memory, access to the portal, and what secret-desk deliberately does not do.
